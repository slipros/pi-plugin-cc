# Агенты pi из Claude Code

Все команды — через companion-скрипт в каталоге этого скилла:

```bash
node "<skill-dir>/scripts/pi-companion.mjs" <команда> [флаги] [текст]
```

`<skill-dir>` — базовый каталог скилла, указанный в начале сообщения о его запуске. Дальше в примерах он опускается ради краткости.

| Команда | Назначение |
| --- | --- |
| `delegate [флаги] <задача>` | Отдать задачу агенту pi |
| `review [флаги] [фокус]` | Read-only ревью рабочего дерева или ветки |
| `watch [job-id] [--follow] [--tail N]` | Транскрипт работы агента |
| `steer [job-id] [--follow-up] <текст>` | Отправить указание работающему агенту |
| `status [job-id] [--all]` | Список задач и их состояние |
| `result [job-id]` | Итог завершённой задачи |
| `cancel [job-id]` | Остановить задачу |
| `models [поиск]` | Каталог моделей, пресеты, роли |
| `setup` | Проверка установки pi и конфигурации |

## Правила работы

1. **Не делай работу за pi.** Вывод команды возвращай пользователю как есть, без пересказа. Не исправляй то, что нашло ревью, и не доделывай задачу за агента, пока пользователь об этом не попросил.
2. **Долгие задачи — в фон.** `delegate --background` + `Bash(run_in_background: true)`. Форграунд оправдан только для узкого вопроса. Сомневаешься — спроси один раз через `AskUserQuestion` («Run in background» / «Wait for results»).
3. **Роль и права выбирай осознанно**: `explorer` для исследования, `fixer` для правки кода, `reviewer`/`adversarial` для критики. Если задача не требует правок — добавляй `--read-only`.
4. **Модель**: если пользователь назвал — используй её. Если нет — не выдумывай, оставь дефолт и укажи в ответе, какая модель отработала.
5. **После write-прогона** покажи `git status --short` и `git diff --stat`. Коммиты не делай.
6. Если pi упал — сообщи job-id, ошибку и что в логе. Не переписывай задачу молча.

## Выбор модели

```bash
delegate --model opencode-go/kimi-k3 --thinking high  "почини падающий тест авторизации"
delegate --provider anthropic --model claude-sonnet-5 "переделай логику ретраев"
delegate --preset fast "прогони линтер и объясни ошибки"
```

- `--model` принимает `provider/id`, короткое имя, glob (`anthropic/*`) и нечёткое совпадение; несуществующее имя даёт предупреждение, но всё равно уходит в pi.
- `--thinking off|minimal|low|medium|high|xhigh|max`.
- `--preset <имя>` — набор из `.claude/pi/config.json`.
- `models [поиск]` показывает каталог с контекстом и поддержкой thinking.

## Системный промт агента

Порядок приоритета: `--system-prompt` → `--role` → `.claude/pi/SYSTEM.md` проекта.

```bash
delegate --role explorer   "как устроено возобновление сессий?"
delegate --role fixer      "сделай флейки-тест детерминированным"
delegate --system-prompt @.claude/pi/prompts/dba.md "разбери план запроса"
delegate --append-system-prompt "Отвечай по-русски" --role reviewer "…"
```

Встроенные роли: `reviewer`, `adversarial`, `fixer`, `explorer`. Свои — файлы `.claude/pi/roles/<имя>.md` в репозитории или `~/.claude/pi/roles/<имя>.md`; одноимённый файл перекрывает встроенную роль. `--append-system-prompt` (можно повторять) и `.claude/pi/APPEND_SYSTEM.md` дополняют промт, а не заменяют его.

## Инструменты агента

Встроенные инструменты pi: `read`, `bash`, `edit`, `write`, `grep`, `find`, `ls`. По умолчанию `delegate` разрешает всё, `review` — только чтение.

```bash
delegate --read-only "разберись, почему падает сборка"     # read, grep, find, ls
delegate --tools read,grep,find,ls,bash "воспроизведи баг, ничего не меняя"
delegate --exclude-tools bash "поправь типы, команды не запускай"
delegate --no-tools "просто подумай вслух над архитектурой"
```

Новые инструменты дают расширения pi — включая MCP-серверы через `pi-mcp-adapter`, который читает `.mcp.json` проекта:

```bash
delegate --extension npm:pi-mcp-adapter "сходи в БД через MCP и посчитай строки"
delegate --extension ./tools/my-ext.ts --skill ./skills/db "…"
delegate --no-extensions "чистый прогон без сторонних инструментов"
```

У pi **нет песочницы**: `bash`, `edit`, `write` работают с правами пользователя. Давай их только когда задача действительно требует изменений.

## Наблюдение за работой агента

```bash
watch                    # транскрипт последней (или текущей) задачи
watch --tail 20          # только хвост
watch <job-id> --follow  # живой поток, пока задача не завершится
```

Транскрипт показывает ходы, вызовы инструментов с аргументами и результатами, очередь указаний и ответы агента с расходом токенов. Для непрерывного наблюдения пользователю удобнее запустить `--follow` у себя в терминале через `!`, а не ждать его в чате: команда не завершится, пока задача идёт.

`status` даёт короткую сводку по всем задачам, `result` — итоговый ответ.

## Управление на лету

Пока задача выполняется, ей можно отправить указание:

```bash
steer "хватит читать файлы, переходи к правке"
steer <job-id> "сфокусируйся на internal/auth"
steer --follow-up "когда закончишь, добавь тесты"
```

- `steer` доставляется после текущего хода агента, до следующего обращения к модели — это способ развернуть агента, пока он работает.
- `--follow-up` доставляется, когда агент закончит текущую работу.
- Если задача уже завершилась, сообщение уходит как новый промпт в ту же сессию.
- Работает только на движке `rpc` (он по умолчанию). У `--engine json` канала управления нет.

`cancel` сначала пробует мягкий `abort` (сессия pi остаётся целой и результат частично сохраняется) и только потом убивает процесс.

## Продолжение сессии

Каждый прогон сохраняет id сессии pi. Продолжить:

```bash
delegate --session last "теперь примени первый вариант"
delegate --session <session-id> "…"
delegate --fresh "…"                 # принудительно новая сессия
```

Пользователь может открыть ту же сессию у себя: `pi --session <session-id>`.

## Конфигурация

Необязательна. `~/.claude/pi/config.json` — личные дефолты, `<repo>/.claude/pi/config.json` — проектные (перебивают личные, флаги перебивают оба).

```json
{
  "defaults": { "model": "opencode-go/glm-5.2", "thinking": "medium" },
  "presets": {
    "fast":  { "model": "opencode-go/deepseek-v4-flash", "thinking": "off" },
    "audit": { "model": "opencode-go/kimi-k3", "role": "adversarial", "readOnly": true }
  },
  "commands": { "review": { "preset": "audit" } },
  "roles": { "go-reviewer": ".claude/pi/roles/go-reviewer.md" }
}
```

Если что-то не работает — начни с `setup`: он покажет, найден ли бинарь pi, есть ли доступные модели, какие конфиги подхвачены и где лежит состояние задач.
